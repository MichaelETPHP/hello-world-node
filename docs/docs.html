02 — Git Setup

Install & Configure Git

Install Git on Windows

Download Git from git-scm.com and install with default settings. Verify installation:

git --version
# Expected output: git version 2.x.x

Configure Your Identity

Run these once — Git uses this info for every commit you make:

git config --global user.name "Your Name"
git config --global user.email "your@email.com"

Verify your config:

git config --list

Generate SSH Key

SSH lets you connect to GitHub without typing your password every time.

# Generate SSH key
ssh-keygen -t ed25519 -C "your@email.com"

# Press Enter 3 times (accept all defaults)

Copy Your Public Key

# Windows Command Prompt
type %USERPROFILE%\.ssh\id_ed25519.pub

# Windows PowerShell
Get-Content ~/.ssh/id_ed25519.pub

# Open in Notepad
notepad %USERPROFILE%\.ssh\id_ed25519.pub
Your key looks like this

ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... your@email.com — copy the entire line including ssh-ed25519 at the start and your email at the end.

Remove Stored Password (Security)

Never store your password in Git config:

git config --global --unset user.password
03 — GitHub

Connect to GitHub

Add SSH Key to GitHub

1

Go to GitHub Settings

Login to github.com → click profile picture → Settings

2

SSH and GPG Keys

Left sidebar → SSH and GPG keys → click New SSH key

3

Add Your Key

Title: My Laptop   Key type: Authentication Key   Paste your key → Save

4

Test Connection

ssh -T git@github.com
# Expected: Hi YourName! You've successfully authenticated.

Create a Repository

On github.com → click + → New repository → fill in name → set Private → click Create.

Push Your Project to GitHub

# Navigate to your project folder
cd /path/to/your/project

# Create .gitignore first
echo "node_modules/" >> .gitignore
echo ".env" >> .gitignore
echo "*.log" >> .gitignore

# Initialize, commit and push
git init
git add .
git commit -m "initial commit"
git branch -M main
git remote add origin git@github.com:yourusername/your-repo.git
git push -u origin main
✓ Done

Refresh your GitHub repo page — your code is now live on GitHub.

04 — cPanel

cPanel Node.js Setup

Create Node.js Application

Login to cPanel → search Node.js → click Create Application

FieldValue
Node.js version24.x (recommended)
Application modeProduction
Application rootyour-app-folder
Application URLyoursubdomain.yourdomain.com
Startup fileapp.js
⚠ Important

The Application root folder name must match the folder your subdomain points to. Check cPanel → Domains to verify.

Your app.js Must Use process.env.PORT

cPanel assigns a random port — never hardcode port 3000:

const http = require('http');

const port = process.env.PORT || 3000; // ← always use this

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/html' });
  res.end('<h1>Hello World</h1>');
});

server.listen(port, () => {
  console.log(`Server running on port ${port}`);
});

Check Generated .htaccess

After creating the app, cPanel auto-generates a .htaccess file. Verify it via cPanel Terminal:

cat /home/yourusername/your-app-folder/.htaccess

# Should show:
# PassengerAppRoot "/home/yourusername/your-app-folder"
# PassengerBaseURI "/"
# PassengerNodejs "/home/yourusername/nodevenv/your-app-folder/24/bin/node"
# PassengerAppType node
# PassengerStartupFile app.js
05 — Subdomain

Subdomain Setup

Create a Subdomain in cPanel

1

Go to Domains

cPanel → search Domains → click Create A New Domain

2

Enter Subdomain

Type: lms.yourdomain.com — cPanel automatically sets the document root to /lms

3

Verify Document Root

In the Domains list, confirm the Document Root shows /your-folder-name — this must match your Node.js Application root.

Verify Subdomain → Folder Mapping

# cPanel → Domains
# You should see:
# lms.yourdomain.com  →  Document Root: /lms

# This means your subdomain serves files from:
# /home/yourusername/lms/
Key Rule

Subdomain document root folder = Node.js application root folder = GitHub repo folder. All three must be the same folder.

06 — Git on cPanel

cPanel Git Version Control

Clone Your GitHub Repo to cPanel

1

Open Git Version Control

cPanel → search Git Version Control → click Create

2

Fill In Details

Clone URL: https://github.com/yourusername/your-repo.git
Repository Path: /home/yourusername/your-app-folder
Repository Name: your-repo-name
3

Click Create

cPanel clones the repo. You'll see a success notification when done.

Deploy / Pull Updates

After pushing new code to GitHub, pull it to cPanel:

# Option 1 — cPanel GUI
# Git Version Control → Manage → Update from Remote → Deploy HEAD Commit

# Option 2 — cPanel Terminal
cd /home/yourusername/your-app-folder
git pull origin main

Add .cpanel.yml for Auto Deploy

Create this file in your project root so cPanel knows how to deploy:

# .cpanel.yml
---
deployment:
  tasks:
    - export DEPLOYPATH=/home/yourusername/your-app-folder
    - /bin/cp -R ./* $DEPLOYPATH

Force Pull (Overwrite Server Changes)

cd /home/yourusername/your-app-folder

# Discard any server-side changes
git fetch origin
git reset --hard origin/main
07 — Permissions

Fix Folder Permissions

⚠ Most Common Cause of 404

When cPanel creates a Node.js app folder, permissions default to 700 (drwx------) — the web server cannot read it. Always fix permissions after setup.

Understanding Linux Permissions

PermissionMeaningWeb Server Access
700 (drwx------)Owner only❌ Blocked
755 (drwxr-xr-x)Owner + read for all✅ Works
644 (-rw-r--r--)Owner write + read for all✅ Works

Fix Commands — Run After Every New Deployment

# Fix the app folder
chmod 755 /home/yourusername/your-app-folder

# Fix key files
chmod 644 /home/yourusername/your-app-folder/.htaccess
chmod 644 /home/yourusername/your-app-folder/app.js

# Fix all files recursively
find /home/yourusername/your-app-folder -type f -exec chmod 644 {} \;
find /home/yourusername/your-app-folder -type d -exec chmod 755 {} \;

Restart After Fixing

# Via terminal
touch /home/yourusername/your-app-folder/tmp/restart.txt

# Or via cPanel
# Node.js Selector → STOP → SAVE → RESTART
08 — Daily Workflow

Push & Deploy Workflow

Every Day — 4 Commands

# 1. Check what changed
git status

# 2. Stage all changes
git add .

# 3. Commit with message
git commit -m "feat: describe what you changed"

# 4. Push to GitHub
git push origin main

After Pushing — Update cPanel

# Option A — Via cPanel Terminal
cd /home/yourusername/your-app-folder
git pull origin main
touch tmp/restart.txt

# Option B — Via cPanel GUI
# Git Version Control → your repo → Manage → Update from Remote
# Node.js Selector → Restart

Good Commit Message Examples

TypeExample
feat:feat: add user login page
fix:fix: correct port configuration
update:update: change welcome page text
docs:docs: add README file
style:style: update CSS colors

Working with Branches

# Create a new branch for new features
git checkout -b feature/new-dashboard

# Work on your feature, then commit
git add .
git commit -m "feat: new dashboard layout"

# Merge back to main when ready
git checkout main
git merge feature/new-dashboard
git push origin main

10 — Troubleshooting

Common Issues & Fixes

404 Not Found

CauseFix
Wrong folder permissionschmod 755 /home/user/appfolder
Wrong Application URLNode.js Selector → change to correct subdomain
App not runningNode.js Selector → Restart
Missing .htaccessStop app → Save → Restart to regenerate

Git Pull Error — Local Changes

# Error: Your local changes would be overwritten by merge

# Fix: discard server changes and force pull
git fetch origin
git reset --hard origin/main

SSH Not Working

# Regenerate SSH key
ssh-keygen -t ed25519 -C "your@email.com"

# Copy key (Windows)
type %USERPROFILE%\.ssh\id_ed25519.pub

# Test connection
ssh -T git@github.com

App Crashes on cPanel

# Check error log
cat /home/yourusername/appfolder/stderr.log

# Check if node is running
ps aux | grep node

# Restart the app
touch /home/yourusername/appfolder/tmp/restart.txt

Wrong Remote URL (HTTPS → SSH)

# Switch from HTTPS to SSH
git remote set-url origin git@github.com:username/repo.git

# Verify
git remote -v
✓ Quick Checklist

1. Folder permissions = 755  |  2. App URL = correct subdomain  |  3. Startup file = app.js  |  4. Use process.env.PORT  |  5. App status = Running
